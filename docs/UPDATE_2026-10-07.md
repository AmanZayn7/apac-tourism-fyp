## Critical notebook corrections

Ridge rolling features no longer include the current target, and pandemic rows are preserved before lagging. The YoY tree experiments are explicitly reformulated as log-level forecasts to eliminate zero-denominator infinities and current-target rolling leakage. Full-series winsorization is removed. Contemporary hotel/search inputs with unverified availability are excluded. Ridge selection is chronological, scaling is fit inside each training window, and all methods are assessed on common full-year recursive windows rather than mixing one-step predictions with four-month baselines.

Singapore's missing original recovery-index file is not fabricated: corrected studies explicitly use the supplied final Singapore CSV as a new experiment. Original leaky scores are not presented as comparable benchmarks. Negative R², operational forecast bounds and error-band limitations remain disclosed.

## Remaining limits

The supplied observations end in December 2024. The honest outlook is **January–December 2025**, clearly labelled as a historical forecast. Moving it to 2026 without new observations would misrepresent the model's origin. Newer source data is needed for a current forecast.

Upstream provenance and Hong Kong filling remain undocumented; Bangkok is a Thailand proxy with unverified city-level coverage. The original Singapore input remains unavailable. Correcting downstream code cannot certify upstream data preparation.

Browser automation was unavailable, so desktop/mobile pixel appearance and real browser download interaction are not visually certified. Application behavior, chart content, SVG validity and value integrity are tested. Docker is unavailable locally; the updated container and CI configuration have not been run on a remote host. Live public deployment still needs a repository and authenticated hosting connection. See `DEPLOYMENT.md` for the exact steps.

## Notebook CI reconciliation adjustment

A subsequent review found that the notebook CI step compared Linux re-runs with a macOS-built artifact at `rtol=1e-8`, which is too strict for the RF/XGBoost tree implementations across platforms. The reported illustrative difference of 2,915,544 versus 2,916,162 is 0.0212%; that Linux run was not independently available here. The corrected notebooks now use 0.1% relative tolerance for tree **monthly forecasts** and 1% for their validation MAEs, while baseline and Ridge comparisons retain `rtol=1e-8`. Dates and the validation-selected model still have to match exactly. A controlled tolerance check accepted the reported pair and rejected a 1% forecast alteration. All nine notebooks were re-executed after the change. Docker's Linux daemon was unavailable locally, so a real GitHub CI run is still needed to confirm the Linux result.
